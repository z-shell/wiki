The annex maps short labels to groups of plugins and applies a curated ice list to each member. The labels and their ice lists live in the [z-a-meta-plugins.plugin.zsh][] file; this page documents the current catalog and is the [migration guide](#migration-from-earlier-catalogs) that the annex links when a label changed meaning.

:::tip

- Propose a new group in a new [issue][issues/new]
- The `@` prefix avoids syntax conflicts, e.g. `zi light @<meta-plugin-name>`
- Before installing any plugin, visit its repository to verify that your system is supported and meets other requirements

:::

## Usage of meta-plugins {/* #usage-of-meta-plugins */}

The following snippets are examples of how to install meta-plugins:

```zi
zi light @annexes
```

```zi
zi light-mode for @annexes @zsh-users @console-tools
```

```zi showLineNumbers
zi light-mode for z-shell/z-a-meta-plugins \
  @annexes @ext-git @zsh-users
```

```zi showLineNumbers
zi light-mode for @annexes \
  skip'zsh-completions' @zsh-users \
  skip'eza ripgrep' @console-tools
```

The `skip'…'` ice removes members from the group that follows it. A token matches a member by its full ID (`sharkdp/fd`), by its repository name (`fd`) or by a nested label (`fuzzy` inside `@ext-git`). A token that names a member of a nested label is forwarded to that label, so `skip'fzf' @ext-git` loads the Git tools without fzf. A token that matches nothing is reported with a link to this page; see [Migration from earlier catalogs](#migration-from-earlier-catalogs) for the labels that changed.

### Summary of the meta-plugins {/* #summary-of-the-meta-plugins */}

It consumes time to:

- Constantly, over and over collect some new interesting plugins to install/load.
- Over and over reconstruct the new findings on the new machines.
- Constantly extend and tweak the ice list of each plugin, so that it's hard on the eyes, especially for an outsider.

```mdx-code-block
<APITable>
```

| Problem                                               | Solution                                                                                                                                                                                                                                                     |
| :---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| (1) _finding new plugins_                             | The annex contains a curated list of plugins, e.g. the console tools `fd`, `bat`, `eza` and `ripgrep`.                                                                                                                                                       |
| (2) _reconstructing the findings in new environments_ | It's easy to say and memorize e.g. `zi light @console-tools`: one label pulls a group of plugins and also the curated default ice list for each of them.                                                                                                     |
| (3) _constant increase of complexity of the commands_ | The provided ices for each plugin are handled transparently and automatically; care is given to each ice list so that the plugin loads without any glitches (e.g. without the "No files for compilation found." message and other, even such slight issues). |

```mdx-code-block
</APITable>
```

Other unique benefits of the meta-plugins annex:

```mdx-code-block
<APITable>
```

| Benefit                                                     | Description                                                                                                                                                                                                                                                                                |
| :---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Provisioning checks                                         | A group whose recipes need an installer annex, a toolchain or a binary on `PATH` is refused with a message that names the missing piece, instead of failing halfway. @annexes loads the four installer annexes in one step.                                                                |
| Flexible disabling of chosen sub-plugins in any meta-plugin | A meta-plugin can contain many sub-plugins and it's possible to skip installing some of them by the **skip'plugin-1 plugin-2…'** ice, e.g. `zi skip'ripgrep fd' light @console-tools`. This way, despite some meta-plugins being broad, the user still has control over what is installed. |
| Common from-source meta plugins                             | For the plugins that provide binary programs it is often the case that a meta-plugin exists that builds the program from source (e.g. the **fuzzy** meta-plugin and its **fuzzy-src** counterpart). This is handy when there is no release binary for your machine.                        |

## Migration from earlier catalogs {/* #migration-from-earlier-catalogs */}

The catalog was rebuilt in [z-a-meta-plugins#84][annex-84]: every group was audited, members that were archived, duplicated or broken were removed, and three author-named labels were retired. A startup file written for the earlier catalog keeps working, but the annex now tells you what changed:

- A retired label (`@z-shell`, `@z-shell+`, `@sharkdp`) installs nothing, keeps the requests that follow it and prints a notice once per session with a link to this page.
- A deprecated label (`@annexes+`) still loads, with the same once-per-session notice.
- A `skip'…'` token that matches no member of its group is reported on every load, together with the group's current members.

Each subsection below lists what the label used to install, what it does now, why, and the exact command for anything that is no longer part of the group. The ice lists are based on the ones the annex used before the cleanup, written as plain commands: the annex-only details (a `compile'…'` of the handler, a guard that skipped a command already on `PATH`) are left out, so a recovered plugin installs and loads in the usual way rather than exactly as the group did. Every command was run once against the current annex; the run log is attached to [wiki#919][wiki-919].

Before running a recovery command:

- Commands with `sbin` or `null` need the [bin-gem-node][] annex and commands with `cargo'…'` need the [rust][] annex. `zi light @annexes` loads both.
- An ID that starts like an ice name (`sharkdp/…` and `sh`, `git-quick-stats/…` and `git`, `cargo-…` and `cargo`) is read by Zi as an ice; the `@` prefix on such IDs marks them as plugins and is not a meta-plugin label.
- Release downloads with `from'gh-r'` select an asset by target triple. The annex resolves it from `$OSTYPE/$CPUTYPE`; replace `x86_64-unknown-linux-musl` in the commands below with your row:

| `$OSTYPE` / `$CPUTYPE`           | Target triple                |
| -------------------------------- | ---------------------------- |
| `linux*` / `x86_64`              | `x86_64-unknown-linux-musl`  |
| `linux*` / `aarch64` or `arm64`  | `aarch64-unknown-linux-musl` |
| `darwin*` / `x86_64`             | `x86_64-apple-darwin`        |
| `darwin*` / `aarch64` or `arm64` | `aarch64-apple-darwin`       |

### @z-shell {/* #migrate-z-shell */}

- Previously: [F-Sy-H][], [H-S-MW][], [zsh-diff-so-fancy][].
- Now: retired; the label installs nothing and prints a notice once per session.
- Reason: an author-named bundle mixed a highlighter, a history widget and a Git pager that have nothing to do with each other ([z-a-meta-plugins#77][annex-77]).

F-Sy-H is the highlighter of `@zsh-users+fast`; load that profile, or F-Sy-H alone. Load the other two members explicitly:

```zi
zi lucid for z-shell/F-Sy-H
zi lucid compile'functions/h*~*.zwc' for z-shell/H-S-MW
zi lucid as'program' pick'bin/diff-so-fancy' atpull'git submodule update --init --recursive' for z-shell/zsh-diff-so-fancy
```

### @z-shell+ {/* #migrate-z-shell+ */}

- Previously: [zsh-select][], [zconvey][], [zui][], [zflai][].
- Now: retired; the label installs nothing and prints a notice once per session.
- Reason: the bundle put specialized tools behind a default label ([z-a-meta-plugins#78][annex-78]). zui is a member of `@zsh-tools`.

```zi
zi lucid blockf for z-shell/zui
zi lucid for z-shell/zsh-select
zi lucid sbin'cmds/zc-bg-notify;cmds/plg-zsh-notify' for z-shell/zconvey
zi lucid for z-shell/zflai
```

The zconvey command needs the bin-gem-node annex for `sbin`.

### @sharkdp {/* #migrate-sharkdp */}

- Previously: [fd][], [bat][], [hexyl][], [hyperfine][], [vivid][].
- Now: retired; the label installs nothing and prints a notice once per session.
- Reason: the tools were split by workflow instead of by author ([z-a-meta-plugins#79][annex-79]). fd and bat are members of `@console-tools`.

```zi
zi lucid as'program' from'gh-r' bpick'*x86_64-unknown-linux-musl.tar.gz' pick'hexyl-*/hexyl' for @sharkdp/hexyl
zi lucid as'program' from'gh-r' bpick'*x86_64-unknown-linux-musl.tar.gz' pick'hyperfine-*/hyperfine' for @sharkdp/hyperfine
zi lucid as'program' from'gh-r' bpick'*x86_64-unknown-linux-musl.tar.gz' pick'vivid-*/vivid' for @sharkdp/vivid
```

Replace the target triple with your row from the table above. hexyl and hyperfine publish no Linux ARM64 asset; install them from a system package there.

### @annexes+ {/* #migrate-annexes+ */}

- Previously: `@annexes` plus [submods][], [default-ice][], [test][], [unscope][] and [eval][].
- Now: deprecated; loads exactly what `@annexes` loads, with a notice once per session.
- Reason: the optional annexes are capabilities to select individually, not a default bundle ([z-a-meta-plugins#61][annex-61]).

Replace the label with `@annexes` and load the optional annexes you use:

```zi
zi lucid compile'functions/.*submods*~*.zwc' for z-shell/z-a-submods
zi lucid for z-shell/z-a-default-ice
zi lucid for z-shell/z-a-test
zi lucid for z-shell/z-a-unscope
zi lucid compile'functions/.*ev*~*.zwc' for z-shell/z-a-eval
```

### @console-tools {/* #migrate-console-tools */}

- Previously: fd, bat, hexyl, hyperfine, exa, ripgrep.
- Now: [fd][], [bat][], [eza][], [ripgrep][].
- Reason: exa is archived and eza is its maintained fork; hexyl and hyperfine moved out of the default group ([z-a-meta-plugins#64][annex-64]).

Rename `skip'exa'` to `skip'eza'`. A `skip` token naming hexyl, hyperfine or exa now matches nothing and is reported; remove it. To keep hexyl or hyperfine, use the commands under [@sharkdp](#migrate-sharkdp). eza publishes a release binary for Linux x86_64 only; on other platforms install it from a system package before loading the group, or add `skip'eza'`.

### @console-style {/* #migrate-console-style */}

- Previously: [dircolors-material][] (package), [vivid][].
- Now: [zsh-eza][], the `ls` aliases built on eza; the group requires `eza` on `PATH`.
- Reason: two color providers in one group overrode each other ([z-a-meta-plugins#65][annex-65]).

Drop the label if you do not want the aliases. To keep the previous members:

```zi
zi lucid pack for dircolors-material
zi lucid as'program' from'gh-r' bpick'*x86_64-unknown-linux-musl.tar.gz' pick'vivid-*/vivid' for @sharkdp/vivid
```

### @zsh-users+fast {/* #migrate-zsh-users+fast */}

- Previously: F-Sy-H, zsh-autosuggestions, zsh-completions, [zsh-fancy-completions][].
- Now: [zsh-completions][], [zsh-autosuggestions][], [F-Sy-H][], in the order completion setup requires.
- Reason: the extra completion set is optional and its ownership of completion initialization conflicted with zsh-completions ([z-a-meta-plugins#63][annex-63]).

To keep zsh-fancy-completions, load it before the profile:

```zi
zi lucid compile'{lib/*.zsh*~*.zwc,functions/{.*,*}*~*.zwc}' for z-shell/zsh-fancy-completions
```

### @fuzzy {/* #migrate-fuzzy */}

- Previously: fzf, fzy, skim, peco.
- Now: [fzf][] only, the `native+keys` package profile.
- Reason: four competing finders installed four sets of key bindings; the skim recipe called an install script that upstream removed ([z-a-meta-plugins#66][annex-66]).

The removed finders have no annex recipe. Install [skim][], [fzy][] or [peco][] from a system package or by following the instructions in their repositories.

### @fuzzy-src {/* #migrate-fuzzy-src */}

- Previously: fzf-go, fzy, skim-cargo, peco-go.
- Now: [fzf][] built from source, the `default+keys` package profile under the `fzf-go` ID.
- Reason: one backend per group, and the group refuses to load next to `@fuzzy` ([z-a-meta-plugins#67][annex-67]).

The removed source builds have no annex recipe; see [@fuzzy](#migrate-fuzzy) for the upstream projects.

### @ext-git {/* #migrate-ext-git */}

- Previously: git-open, git-recent, git-my, git-quick-stats, git-now, git-extras, forgit, gitignore.plugin.zsh, tig.
- Now: `@fuzzy`, [forgit][], [git-open][].
- Reason: the group was rebuilt around tools that share the fzf backend; the others are unrelated to each other and two of them need a build toolchain ([z-a-meta-plugins#68][annex-68]).

Load the bin-gem-node annex first (`zi light @annexes`), then the tools you use:

```zi
zi lucid null sbin for paulirish/git-recent
zi lucid null sbin for davidosomething/git-my
zi lucid null sbin atload'export _MENU_THEME=legacy;' for @git-quick-stats/git-quick-stats
zi lucid null sbin for iwata/git-now
zi lucid as'completion' blockf atclone'cp -vf etc/git-extras-completion.zsh _git-extras-completion' atpull'%atclone' make'PREFIX=$ZPFX MANPREFIX=$ZPFX/man/man1' nocompile for tj/git-extras
zi lucid for voronkovich/gitignore.plugin.zsh
zi lucid binary as'program' atclone'make configure; ./configure' atpull'%atclone' make'prefix=$ZPFX install' for jonas/tig
```

git-extras needs `make`; tig needs `make`, `autoconf` and the ncurses headers.

### @rust-utils {/* #migrate-rust-utils */}

- Previously: `rust-toolchain` (a rustup-managed toolchain inside plugin storage) and eight cargo extensions.
- Now: `cargo-extensions`, which builds cargo-expand and cargo-audit with the toolchain already on your `PATH`.
- Reason: a toolchain owned by the plugin manager shadowed the user's rustup and every extension was compiled on first load ([z-a-meta-plugins#72][annex-72]).

Install the toolchain with [rustup][]. For any other extension, use the `cargo'…'` ice of the [rust][] annex with the crate name. The exception is `cargo-tree`: Cargo provides `cargo tree` itself, so it was removed from the group and should not be installed ([z-a-meta-plugins#72][annex-72]). For example:

```zi
zi lucid as'program' cargo'cargo-outdated' pick'bin/cargo-outdated' teleid'z-shell/0' for @cargo-outdated
```

### @zunit {/* #migrate-zunit */}

- Previously: color, revolver, zunit from the archived `zdharma` organization.
- Now: [zunit][], which bundles the helper libraries it needs.
- Reason: the framework moved to `z-shell/zunit` and builds its own dependencies ([z-a-meta-plugins#70][annex-70]).

Nothing to do; `skip'color'` or `skip'revolver'` now matches nothing and is reported.

### @ohmyzsh-lib {/* #migrate-ohmyzsh-lib */}

- Previously: twelve library snippets named without their file suffix (`OMZL::git`, `OMZL::history` and so on).
- Now: thirteen snippets named by their full file name, with `OMZL::async_prompt.zsh` first.
- Reason: the current `lib/git.zsh` registers its prompt helpers through `lib/async_prompt.zsh`, which the group did not load, and the snippet IDs now carry the actual file names under `lib/` ([z-a-meta-plugins#75][annex-75]).

Nothing to install. A `skip'…'` token matches a snippet member by the start of its ID or by its file name, so `skip'git'` no longer matches and is reported; write `skip'OMZL::git'` or `skip'git.zsh'`.

### Labels that kept their members {/* #migrate-unchanged-labels */}

`@zsh-users`, `@zsh-tools`, `@node-utils`, `@py-utils`, `@prezto` and `@romkatv` received recipe fixes only. `@py-utils` keeps a `PYENV_ROOT` that is already set; export it before the group if your interpreters live outside `~/.pyenv`.

### Recipes that belonged to no label {/* #migrate-orphan-recipes */}

The annex also carried ice lists for plugins that no label selected. They were removed with the retired labels; load any of them explicitly:

```zi
zi lucid null sbin for Fakerr/git-recall
zi lucid pack for @github-issues
zi lucid pack atinit'GIT_PROJECTS=z-shell/zi GIT_SLEEP_TIME=700;' for @github-issues-srv
zi lucid for hlissner/zsh-autopair
zi lucid for urbainvaes/fzf-marks
zi lucid for z-shell/zi-console
zi lucid for z-shell/zsh-navigation-tools
zi lucid for z-shell/zsh-unique-id
zi lucid for z-shell/z-a-linkbin
zi lucid compile'functions/.*lman*~*.zwc' for z-shell/z-a-linkman
zi lucid for z-shell/z-a-man
```

Two of these print a message that is not caused by the recipe: z-a-man reports that its `hpricot` gem fails to build on Ruby 3.4 and loads without it, and `@github-issues-srv` prints "needs to be loaded as service" during its first installation because the profile's `service''` ice applies from the next shell on.

### Worked example {/* #migration-worked-example */}

A startup file written for the earlier catalog:

```zi showLineNumbers
zi lucid for light-mode \
  skip'ripgrep peco tig bat exa hexil hyperfine fd' @console-tools \
  skip'dircolors-material' @console-style \
  skip'F-Sy-H' @z-shell \
  @romkatv \
  @zsh-users+fast
```

Line by line:

1. `skip'ripgrep peco tig bat exa hexil hyperfine fd' @console-tools` installed hexyl only: `hexil` matched nothing and `peco` and `tig` were never members. On the current catalog it installs eza and reports five unmatched tokens. Replace it with the hexyl command from [@sharkdp](#migrate-sharkdp), and keep `skip'ripgrep bat fd' @console-tools` only if you want eza.
2. `skip'dircolors-material' @console-style` installed vivid. The group now provides eza aliases and requires eza, so replace it with the vivid command from [@console-style](#migrate-console-style).
3. `skip'F-Sy-H' @z-shell` installed H-S-MW and zsh-diff-so-fancy. The label is retired; use the two commands from [@z-shell](#migrate-z-shell).
4. `@romkatv` is unchanged.
5. `@zsh-users+fast` no longer includes zsh-fancy-completions; add the command from [@zsh-users+fast](#migrate-zsh-users+fast) before the profile if you want it back.

The same startup file for the current catalog, with `light-mode` applied to every entry:

```zi showLineNumbers
zi lucid light-mode for \
  as'program' from'gh-r' bpick'*x86_64-unknown-linux-musl.tar.gz' pick'hexyl-*/hexyl' @sharkdp/hexyl \
  as'program' from'gh-r' bpick'*x86_64-unknown-linux-musl.tar.gz' pick'vivid-*/vivid' @sharkdp/vivid \
  compile'functions/h*~*.zwc' z-shell/H-S-MW \
  as'program' pick'bin/diff-so-fancy' atpull'git submodule update --init --recursive' z-shell/zsh-diff-so-fancy \
  @romkatv \
  @zsh-users+fast
```
